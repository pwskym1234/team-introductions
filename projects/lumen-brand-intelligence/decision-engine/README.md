## GEO 파서와의 경계

질문 파싱은 GEO에 이미 구현돼 있다고 가정한다. 이 프로젝트는 질문 원문을 다시 분류하지 않고 아래 구조를 받는다.

- `question.intentCodes`: 브랜드 집계에도 쓸 수 있는 통제된 taxonomy
- `symptoms`: 안전 규칙용 코드와 강도
- `screening`: 위험 신호·성인·임신/수유·섭식장애 우려·알레르기 확인의 `yes/no/unknown` 상태
- `constraints`: 확인된 알레르기·질환·식이 제한·현재 보충제
- `nutrition`: 실제 섭취 정보
- `medicationEvents`: 사건 정렬용 시작·증량 시점
- `metrics`: 일별 웨어러블 값과 기기·완전성

원문은 서비스 경계 안에서만 사용하며 브랜드 이벤트에는 넣지 않는다. 브랜드 이벤트는 `brand_aggregate` 범위와 현재 `consentPolicyVersion`이 모두 맞을 때만 생성한다. 안정적인 `anonymousUserId`와 요청별 `anonymousSessionId`는 현재 데모 namespace로 SHA-256 가명처리한다. 운영 환경에서는 회전 가능한 서버 비밀키를 사용하는 HMAC으로 교체해야 한다.

## 처리 순서

1. 서비스 동의 확인
2. 위험 신호·보호 대상 확인: 양성이면 즉시 중단, 미확인이면 정보가치가 가장 큰 질문 하나만 반환
3. 최신 GLP-1 시작·증량 사건에 일별 지표 정렬
4. 같은 기기·단위·완전성과 기준선/이후 기간 검사
5. 절대·백분율·표준화 변화 크기 계산
6. Newey–West/HAC 자기상관 보정, 95% 구간, 근사 p값 계산 후 여러 지표에 Holm 보정
7. 변화·원인·위험·비교·정체·효과 6가지 판정을 각각 생성
8. 안전 중단을 처방약 질문 경계보다 먼저 적용
9. `supportedIntentCodes`로 관련 상품만 검색해 무관 상품을 후보·결측 집계에서 제거
10. 검색된 상품에만 알레르기 표시·금기·중복·상호작용·라벨/근거·가격/재고 Hard filter 적용
11. 통과 후보만 근거 40% + 개인 적합 30% + 데이터 20% + 실행 가능 10% − 관련 판정 불확실성 최대 30점으로 정렬
12. 다양성 중복 보류를 안전 탈락과 별도 상태로 기록
13. 네 칸 설명 생성
14. 브랜드 집계 동의와 정책 버전이 맞을 때만 sanitizer를 통과한 순차 이벤트 생성
15. 요청 안에서 실제 순서를 지킨 이벤트만 퍼널로 집계하고 재방문 사용자는 가명 사용자 단위로 계산

## 6가지 판정의 의미

| 판정 | 오늘 엔진이 하는 일 | 하지 않는 주장 |
|---|---|---|
| 변화 | 개인 기준선 대비 변화량과 불확실성 계산 | 위험·원인·임상 유의성 확정 |
| 원인 | 투약 사건과 변화 시점의 겹침, 교란요인 표시 | 약이 원인이라는 인과 주장 |
| 위험 | 독립 red flag 규칙으로 상품 추천 중단 | 웨어러블 변화만으로 안전 판정 |
| 비교 | 승인된 코호트가 없으면 `comparison_unavailable` | 가짜 백분위·유사 환자 비교 |
| 정체 | 검증된 장기 규칙이 없으면 `plateau_unavailable` | 용량 변경 또는 치료 조정 |
| 효과 | 승인된 n-of-1 프로토콜 없으면 `research_not_approved` | 상품·약 효과 입증 |

6개를 모두 출력하지만, 데이터와 승인이 없는 판정을 억지로 열지 않는 것이 엔진의 정상 동작이다.

## 실행

Node.js 22 이상에서 별도 패키지 설치 없이 실행한다.

```bash
npm test
npm run demo
```

`npm run demo`는 합성 U-01 정상 경로, U-02 안전 중단, U-03 새 기기 데이터 부족과 브랜드 집계를 출력한다.

## 파일

- `src/statistics.ts`: 변화 크기와 통계 불확실성
- `src/products.ts`: Hard filter와 설명 가능한 상품 정렬
- `src/engine.ts`: 6판정과 최종 결정 오케스트레이션
- `src/analytics.ts`: 개인정보 안전 이벤트와 브랜드 집계
- `src/fixtures.ts`: 합성 사용자·상품
- `src/demo.ts`: 전체 실행 예시
- `tests/`: 통계·상품·결정·집계 경계 테스트

## 데모 한계

- 변화 검정은 소표본 해커톤용 HAC 근사이며 임상 검증이 아니다.
- 합성 상품의 출처 URL·가격·재고는 실제 상품 추천에 사용할 수 없다.
- 비교·정체·효과는 필요한 데이터·승인이 없어 의도적으로 닫혀 있다.
- 점수는 효과 확률이나 구매 확률이 아니라 적격 후보 사이의 설명 가능한 정렬값이다.
- 현재 가명화는 데모용 고정 SHA-256 namespace다. 운영 전에는 tenant별 회전 HMAC 키, 동의 철회 원장, 삭제 전파를 구현해야 한다.
- intent taxonomy와 상품 `supportedIntentCodes`는 아직 수동 검수 대상이다. 검색 재현율·오분류율을 실제 라벨 데이터로 검증해야 한다.
