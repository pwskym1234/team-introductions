# Amplitude UI 시스템 정밀 분석과 Lumen 전면 개편 기준

작성일: 2026-10-03  
대상: Lumen 브랜드 인텔리전스 제품 UI  
목적: Amplitude를 표면적으로 흉내 내는 것이 아니라, 분석가가 질문을 만들고 결과를 읽고 다음 행동으로 이어 가는 작업 체계를 제품에 이식한다.

---

## 0. 결론부터

Amplitude다운 화면은 보라색, 카드, 선 그래프 때문에 만들어지지 않는다. 핵심은 아래 다섯 가지다.

1. **분석 문장을 왼쪽에서 만든다.** 이벤트, 사용자 집단, 측정 방식을 일정한 순서로 조립한다.
2. **결과 캔버스가 가장 크다.** 차트와 표가 화면의 주인공이고 장식은 거의 없다.
3. **숫자에서 다음 행동으로 바로 이동한다.** 데이터 점 선택 → 사용자 확인 → 코호트 저장 → 다른 분석 또는 캠페인 활용이 이어진다.
4. **기간·비교·계산 상태가 문맥 가까이에 있다.** 페이지 전체에 흩어 놓지 않고 결과를 해석하는 자리에서 조정한다.
5. **밀도는 높지만 위계는 조용하다.** 작은 글씨를 남발하는 대신 12–14px 본문, 1px 구분선, 4–6px 반경, 제한된 색, 정렬된 숫자로 많은 정보를 안정적으로 보여 준다.

현재 Lumen은 기능은 풍부하지만, 반복 카드·장식 배지·과도한 설명 문장·가짜 상태 문구가 분석 작업보다 먼저 보여 “AI가 만든 SaaS 데모”처럼 느껴진다. 이번 개편은 장식을 줄이고 작업 구조를 전면에 세우는 방향이다.

## 2. Amplitude UI의 전체 골격

### 2.1 전역 내비게이션

관찰되는 패턴:

- 가장 왼쪽에는 제품 영역을 고르는 안정적인 전역 내비게이션이 있다.
- 상단은 `Create`, 최근 항목, 즐겨찾기, 공간, 검색처럼 작업 진입점이 중심이다.
- 현재 프로젝트·공간은 항상 확인할 수 있으나 브랜드 장식보다 작다.
- 활성 메뉴는 강한 그라데이션이 아니라 옅은 배경 또는 텍스트 강조로 구분한다.
- 메뉴 이름은 명사형이고 짧다. 설명은 메뉴 자체에 넣지 않는다.

Lumen 적용:

- `홈 / 질문 분석 / 전환 / 여정 / 고객 그룹 / 상품 / 질문 기록 / 데이터`처럼 1–4음절 중심의 이름을 사용한다.
- “우선 확인할 변화”처럼 문장형 메뉴는 `인사이트`로 줄인다.
- “합성 이벤트 연결됨” 같은 데모 설명은 내비게이션에서 제거하고 데이터 상태 화면에 둔다.

### 2.2 페이지 헤더

관찰되는 패턴:

- 제목이 1차, 소유자·공간·수정 상태는 2차다.
- 저장, 공유, 더보기 같은 작업은 오른쪽에 모인다.
- 설명은 한 줄을 넘기지 않거나 상세 도움말로 밀어낸다.
- “공식”은 신뢰 표시가 실제로 필요할 때만 사용한다. 모든 페이지에 붙이지 않는다.

Lumen 적용:

- 모든 화면에 붙던 `공식 화면`, `브랜드팀 공유 공간`, `모든 변경 저장됨`을 제거한다.
- 제목 아래에는 현재 분석 정의를 한 줄로만 표시한다.
- 저장 상태는 사용자가 수정한 분석에서만 보이게 한다.

### 2.3 분석 편집기와 결과 캔버스

Amplitude는 복잡한 분석을 공통 문법으로 표준화해 왔다. 공식 설명에도 차트 제어를 `이벤트 → 사용자/세그먼트 → 시각화할 지표`의 논리적 패널로 표준화했다고 나온다.

구조:

```text
┌───────────── 분석 정의 ─────────────┬──────────────── 결과 ────────────────┐
│ A  질문 시작                        │ 질문 수 / 전환율 / 기간              │
│    + 조건  + 나누기                 │ [시각화 전환] [기간] [비교]           │
│                                     │                                     │
│ 측정: 고유 질문                     │              차트                   │
│                                     │                                     │
│ 1  모든 사용자                      │─────────────────────────────────────│
│    + 조건  + 행동 조건              │ 세부 결과 표                         │
└─────────────────────────────────────┴─────────────────────────────────────┘
```

세부 원칙:

- 왼쪽 편집기는 대체로 고정 폭이며 스크롤 가능하다.
- 각 행은 색상 문자 토큰(A, B 또는 1, 2), 사람 이름, 원본 이벤트 이름, 조건 작업으로 구성된다.
- 섹션 번호를 커다란 원으로 장식하지 않는다. 구분선과 작은 레이블로 충분히 나눈다.
- `Run/계산`은 정의가 바뀌었을 때 결과를 갱신하는 명확한 주 행동이다.
- 오른쪽 캔버스는 편집기보다 훨씬 넓고 차트-표가 수직으로 이어진다.

## 3. 시각 언어 정밀 분석

### 3.1 색

관찰 기반 역할 체계:

| 역할 | 권장 범위 | 사용처 |
|---|---:|---|
| 바탕 | `#F7F7F8` 계열 | 앱 배경 |
| 표면 | `#FFFFFF` | 캔버스, 표, 팝오버 |
| 강한 텍스트 | `#1D1D22` 계열 | 제목, 핵심 숫자 |
| 보조 텍스트 | `#65656F` 계열 | 메타데이터, 설명 |
| 구분선 | `#E5E5EA` 계열 | 패널, 표 행, 입력 |
| 주 강조 | 청보라 1색 | 활성, 주 버튼, 1차 시리즈 |
| 의미 색 | 초록·주황·빨강 | 상태·경고에만 제한 |

문제 패턴:

- 카드마다 다른 파스텔 배경과 아이콘 박스를 주면 AI 대시보드처럼 보인다.
- 보라·청록·주황을 장식 목적으로 동시에 쓰면 데이터 계열 색과 상태 색의 의미가 충돌한다.
- 시각화 색은 범주 구분에 쓰고, UI 크롬 색은 가능한 중립적으로 둬야 한다.

### 3.2 타이포그래피

권장 계층:

| 용도 | 크기 | 굵기 | 비고 |
|---|---:|---:|---|
| 페이지 제목 | 20–24px | 620–700 | 한 줄 |
| 패널 제목 | 14–16px | 620–680 | 질문형 제목 남발 금지 |
| 본문/표 | 12–13px | 400–550 | 제품의 기본 크기 |
| 버튼/제어 | 12px | 550–650 | 높이 30–34px |
| 메타 | 11px | 400–600 | 상태·날짜 |
| 코드 | 11–12px | 450–600 | 원본 이벤트명 |

현재 화면의 8–10px 텍스트는 정보를 많이 보이게 하는 대신 읽기 어렵게 만든다. 정보 밀도는 작은 글씨가 아니라 정렬, 열 너비, 행 높이, 구분선으로 만든다.

### 3.3 간격

- 4px 단위를 기반으로 한다.
- 제어 안쪽: 6–10px.
- 표 행: 36–44px.
- 패널 내부: 16–20px.
- 패널 사이: 12–16px.
- 페이지 바깥 여백: 20–28px.
- 빈 공간은 큰 히어로 영역보다 차트 가독성과 표 열 분리를 위해 사용한다.

### 3.4 모서리와 그림자

- 앱 패널은 4–6px 반경, 얇은 선, 거의 없는 그림자를 사용한다.
- 팝오버·드로어처럼 떠 있는 요소에만 그림자를 쓴다.
- 둥근 캡슐은 토글·상태에 한정한다.
- 모든 박스를 12–20px로 둥글게 만들면 콘텐츠 종류가 구분되지 않는다.

### 3.5 아이콘

- 14–18px 선형 아이콘, 동일한 선 굵기.
- 아이콘만 있는 버튼은 30–32px 정사각형 클릭 영역과 툴팁/aria-label이 필요하다.
- 의미 없는 반짝이 아이콘은 쓰지 않는다.
- 상태는 아이콘+텍스트로 표시하고 색만으로 전달하지 않는다.

## 4. 제어 요소와 상호작용

### 4.1 드롭다운

- 트리거 안에는 현재 값이 가장 먼저 읽혀야 한다.
- 팝오버 상단 검색은 선택지가 긴 이벤트·속성 목록에만 필요하다.
- 선택 행은 체크, 이름, 부가 설명의 3단 구조다.
- 긴 원본 이름은 잘리지 않도록 툴팁 또는 두 줄 표시를 제공한다.
- 열렸을 때 테두리 또는 focus ring으로 트리거와 팝오버 관계를 보인다.

### 4.2 날짜와 기간 비교

공식 문서상 날짜 선택은 차트 오른쪽 위에 있으며 최근 90일, 직접 지정 기간 등을 제공한다. 기간 비교는 날짜 선택과 가까운 곳에 있고 이전 일·주·월·분기·년 및 고정 시작/종료일, 최대 두 비교 기간까지 지원한다.

Lumen 원칙:

- 날짜를 앱 전체 도구막대에만 두지 말고 결과 헤더에서도 현재 범위를 확인할 수 있게 한다.
- `최근 30일`만 보여 주지 말고 실제 날짜를 함께 표시한다.
- `이전 같은 기간`의 계산 날짜를 팝오버 안에 보여 준다.
- 네이티브 브라우저 기본 select를 사용하지 않는다.
- 모바일에서는 기간 팝오버가 화면 폭을 넘지 않아야 한다.

### 4.3 필터

- 필터는 `속성 / 연산자 / 값`의 문장 순서를 유지한다.
- AND/OR은 조건 행 사이에 보여 주거나 패널 상단에서 명확히 고른다.
- 현재 적용 조건은 도구막대 칩 또는 편집기 안에서 즉시 확인 가능해야 한다.
- 적용 전 예상 표본, 적용 후 실제 표본, 최소 표본 경고를 구분한다.

### 4.4 탭과 시각화 전환

- 탭은 차트 해석 방식을 바꿀 때 쓴다: 전환 / 시간에 따른 전환 / 전환 시간 / 빈도.
- 버튼처럼 입체적으로 보이기보다 밑줄 또는 옅은 선택 배경을 쓴다.
- 동작하지 않는 탭을 데모 장식으로 두지 않는다. 최소한 선택 상태와 내용이 바뀌어야 한다.

### 4.5 피드백 상태

- 로딩: 기존 차트 크기를 유지한 스켈레톤 또는 인라인 계산 상태.
- 빈 결과: 왜 비었는지, 어떤 조건을 풀 수 있는지 제안.
- 오류: 실패 범위와 재시도 동작.
- 저장: 사용자가 저장을 눌렀거나 변경 사항이 있을 때만 표시.
- 최신성: “3분 전” 같은 가짜 실시간 문구 대신 `합성 데이터 생성 시각` 또는 `선택 기간 전체 계산`처럼 정확히 표현한다.

## 5. 시각화별 분석

### 5.1 Event Segmentation / 질문 행동 분석

Amplitude의 Event Segmentation은 이벤트와 속성, 사용자 세그먼트, 측정 방식을 조합하고 결과 차트 아래에 breakdown table을 둔다.

필수 UI:

- 이벤트 A/B 토큰.
- `+ 필터`, `+ 기준별 나누기`.
- 고유 사용자, 이벤트 총합, 빈도, 속성 합/평균 같은 측정 방식.
- 일/주/월 간격, 선/막대/누적/표 전환.
- 현재 값 hover, 데이터 점 click 후 사용자 집단·코호트로 확장.
- 차트 아래 범주별 표와 정렬, 검색, CSV.
- 현재 날짜의 미완성 구간은 점선으로 표시.
- 이전 기간은 같은 색의 약한 점선으로 구분.

Lumen 적용:

- `질문 시작`을 기본 이벤트로 두되 원본 코드 `question_started`는 보조로 노출한다.
- 측정 방식과 나누기 기준은 왼쪽에 모은다.
- 차트 범례는 표의 색과 동일해야 한다.
- 차트 상단의 숫자는 현재 선택한 지표 하나만 크게 보여 주고, 4개 KPI 카드를 반복하지 않는다.

### 5.2 Funnel / 질문→상품 전환

공식 문서의 기본 전환 화면은 각 단계의 converted와 dropped-off를 함께 보여 주는 막대 그래프다. 추가로 시간에 따른 전환, 전환 시간 히스토그램, 특정 이벤트 빈도 보기를 제공한다.

Lumen에서는 사용자가 명시적으로 요구한 “고깔형 곡선 퍼널”을 유지하되 아래 원칙을 적용한다.

- 한 개의 연속 형태로 보이게 하고 각 단계를 별도 카드처럼 쌓지 않는다.
- 폭은 항상 첫 단계 대비 잔존 비율을 정확히 반영한다.
- 단계마다 도달 수, 첫 단계 대비율, 직전 단계 대비율을 동시에 제공한다.
- 클릭하면 아래/오른쪽 검사 패널에서 중앙 전환 시간과 이탈 집단을 보여 준다.
- 가장 큰 이탈은 장식 배지보다 표/주석으로 명확히 표시한다.
- 전환 규칙(순서, 정확한 순서, 어떤 순서든)과 30분 창을 편집기에 둔다.

### 5.3 Journeys

공식 문서상 Pathfinder는 시작 또는 종료 이벤트 주변의 모든 경로와 각 단계 빈도를 보여 주고, 노드를 클릭해 최대 9단계까지 확장한다. 희귀 경로는 `Other`로 묶고, 노드 hover/click으로 상세 경로와 지표를 본다. Journey Map은 전환까지의 구체적 경로와 평균 시간을 파악하는 데 쓴다.

필수 UI:

- 시작점 또는 종료점 명시.
- 단계 수, 반복 이벤트 접기, 희귀 경로 묶기.
- 노드에는 이벤트명과 수/비율.
- 링크 두께는 사용자 수에 비례.
- 같은 열의 노드는 균일 정렬, 겹침 금지.
- 캔버스 확대/축소·맞춤·이동.
- 선택 노드 경로만 강조하고 나머지는 낮은 불투명도로 처리.
- 선택 집단을 코호트나 퍼널로 전환.

### 5.4 Data Tables

공식 문서상 Data Tables는 여러 지표×여러 차원을 한 표에 비교하고, 열 정렬·크기 조절·복사/붙여넣기·최대 5개 상위 group-by·중첩 group-by·열 옵션·행/열 전환을 제공한다.

Lumen 적용:

- 상품 표를 대시보드 카드가 아니라 실제 분석 테이블로 취급한다.
- 헤더 고정, 숫자 오른쪽 정렬, 천 단위, 퍼센트 소수점 일관성.
- 열 메뉴에서 정렬, 필터, 열 숨기기, 이름 변경.
- 셀 데이터 바는 약한 배경으로만 사용하고 숫자를 가리지 않는다.
- 행 클릭은 오른쪽 상세 드로어로 연결한다.

### 5.5 Dashboard / 홈

공식 문서상 대시보드는 이미 저장된 차트·코호트를 반복 모니터링하는 공간이며, 각 항목을 chart/table/KPI 방식으로 표시할 수 있다. 따라서 홈은 새로운 설명 카드 모음보다 저장된 분석과 모니터의 조합이어야 한다.

Lumen 적용:

- 맨 위 4개의 같은 크기 KPI 카드를 없애고, 한 줄 요약 + 핵심 추세 + 전환 + 상품표로 구성한다.
- 인사이트는 별도 반짝이 카드가 아니라 관찰 목록/주석으로 붙인다.
- 각 패널에는 제목, 정의, 기간, 더보기만 둔다.
- “전체 보기”, “분석 열기”는 텍스트 링크보다 예측 가능한 패널 메뉴 또는 클릭 가능한 제목을 쓴다.

### 5.6 Cohorts / 고객 그룹

- 정의, 현재 인원, 최근 계산 시각, 소유자, 동적/스냅샷 여부를 표로 보여 준다.
- 생성기는 행동·속성 조건을 동일한 문장 문법으로 조립한다.
- 작은 집단은 개인정보 기준을 이유와 함께 명확히 차단한다.
- 분석 지점에서 생성한 코호트는 출처 차트 링크를 가진다.

### 5.7 Session / 질문 처리 기록

- 검색과 열 필터가 표 위에 붙는다.
- 리스트는 고정 헤더와 조밀한 행으로 만든다.
- 상세 드로어는 요약 → 시간순 이벤트 → 원본 코드 순서다.
- 개인 건강 원문 미수집 안내는 한 번만, 명확한 위치에 둔다.
- JSON은 기본 접힘으로 두고 사람이 읽는 설명을 먼저 보여 준다.

## 6. 카피와 네이밍 원칙

### 제거해야 할 AI식 카피

- “이 숫자는 어떤 이벤트와 속성으로 만들어졌나요?”처럼 모든 제목을 질문형으로 만드는 습관.
- “근거가 있는 다음 질문”, “우선 확인할 변화”처럼 의미는 좋아 보이지만 메뉴에서 바로 해석되지 않는 추상어.
- “공식 화면”, “모든 변경 저장됨”, “전체 이벤트 계산됨 · 3분 전”처럼 기능적 근거 없이 신뢰감을 연출하는 문구.
- 같은 설명을 페이지 제목, 패널 제목, 본문에서 반복하는 것.

### 사람 중심 네이밍

| 기존 | 개편 |

| 질문 행동 분석 | 질문 분석 |
| 질문→상품 퍼널 | 전환 |
| 사용자 여정 | 여정 |
| 우선 확인할 변화 | 인사이트 |
| 질문 처리 기록 | 질문 기록 |
| 데이터 품질 | 데이터 |
| 어떤 행동을 볼까요? | 이벤트 |
| 무엇을 셀까요? | 측정 |
| 누구를 비교할까요? | 사용자 그룹 |
| 어떤 기준으로 나눌까요? | 나누기 |
| 조건 추가 | 필터 추가 |

도메인 설명이 필요한 곳에서는 쉬운 한국어 이름을 먼저, 기술 코드를 둘째 줄에 둔다.

## 9. 화면별 개편 명세

### 홈

1. 상단: `브랜드 성과` 제목과 기간.
2. 한 줄 요약: 질문 수, 완료율, 상품 노출률, 상세 이동률. 카드 대신 같은 패널의 4열.
3. 좌측 2/3: 질문 추세 차트 + breakdown 표 일부.
4. 우측 1/3: 변화 목록. 아이콘 박스 없음.
5. 전환 패널: 곡선 미니 퍼널 대신 단계별 수평 전환표 또는 한 줄 전환 바.
6. 상품표: 상위 5개와 바로 열기.

### 질문 분석

1. 왼쪽 고정 편집기 288px.
2. 이벤트 / 측정 / 사용자 그룹 / 나누기의 4개 모듈.
3. 오른쪽 상단에 현재 지표와 기간·비교·시각화 제어.
4. 차트 높이 최소 340px.
5. 바로 아래 sticky header 표.

### 전환

1. 왼쪽에 단계 편집, 순서, 전환 창.
2. 오른쪽 상단에 전환 / 시간 추세 / 전환 시간 탭.
3. 핵심 숫자는 `전체 전환율` 하나를 크게, 나머지는 작은 보조 값.
4. 곡선 퍼널 클릭 시 검사 패널.
5. 단계별 표에 도달, 이탈, 단계 전환율, 중앙 시간.

### 여정

1. 시작 이벤트와 방향을 편집기에서 설정.
2. 캔버스 상단에 단계 수, 반복 접기, 희귀 경로, 맞춤/확대/축소.
3. 노드 클릭 시 경로 강조와 오른쪽 인스펙터.
4. `이 경로로 퍼널 만들기`, `고객 그룹 저장` 작업.

### 상품

1. 상단 KPI 카드 제거, 테이블 상단 요약 숫자로 통합.
2. 탭은 전체 / 정보 보완 필요 / 사용자 조건 제외.
3. 상품명 고정 열, 나머지 수평 스크롤.
4. 행 선택 상세 패널에 적격·제외 원인을 분리.

### 고객 그룹·질문 기록·데이터

- 모두 표 중심으로 통일한다.
- 생성/검색/필터는 표 바로 위에 둔다.
- 도움말 카드 대신 열 헤더 도움말과 상세 드로어를 사용한다.

## 10. 구현 완료 판단 기준

### 시각

- 첫 화면에서 동일 형태 KPI 카드 4개가 보이지 않는다.
- 반짝이 아이콘, 색 아이콘 박스, 장식 그라데이션이 없다.
- 기본 본문이 12px 미만으로 내려가지 않는다.
- 패널 반경은 4–6px이며 그림자는 팝오버·드로어에만 있다.
- 하나의 화면에서 주 강조색은 한 가지다.

### 기능

- 기간 프리셋, 직접 기간, 이전 기간 비교가 동작한다.
- 필터 AND/OR, 필드, 값, 적용 전 표본이 동작한다.
- 질문 분석의 측정/나누기 변경이 차트와 표에 함께 반영된다.
- 퍼널 순서 조건이 결과에 반영되고 단계 선택이 가능하다.
- 여정 노드 선택, 단계 수, 반복/희귀 경로 옵션이 동작한다.
- 상품 행과 질문 행에서 상세 드로어가 열린다.
- 고객 그룹 저장이 실제 목록에 추가된다.
- 화면과 기간이 URL에 남는다.

### 데이터 신뢰

- 모든 숫자는 합성 이벤트 원장에서 재계산한다.
- 질문 수, 익명 사용자 수, 질문×상품 평가 수의 분모를 섞지 않는다.
- 개인정보 원문을 저장하거나 화면에 복원하지 않는다.
- 작은 표본 경고와 인과 해석 한계를 유지한다.

### 접근성과 품질

- 모든 아이콘 전용 버튼에 접근 가능한 이름이 있다.
- 키보드 focus가 보인다.
- 표 숫자는 오른쪽 정렬되고 헤더가 스크롤 중 유지된다.
- 1280×720에서 핵심 분석이 가로 스크롤 없이 보인다.
- 900px 이하에서 사이드바와 편집기가 콘텐츠를 가리지 않는다.
- 빌드, lint, 렌더링 테스트, 브라우저 콘솔이 통과한다.

## 11. 하지 않을 것

- Amplitude 상표, 로고, 고유 제품명을 복제하지 않는다.
- 화면을 그럴듯하게 보이기 위한 가짜 실시간 상태를 만들지 않는다.
- 동작하지 않는 버튼을 다수 배치하지 않는다.
- “AI가 찾아준 인사이트”처럼 근거 이상의 확신을 주지 않는다.
- 의료 판단과 마케팅 분석의 경계를 흐리지 않는다.

이 보고서는 이후 UI 수정의 체크리스트이자 검수 기준이다. 구현에서 Amplitude와 다르게 보이는 부분이 있어도, 분석 문장 → 결과 → 세부 집단 → 다음 행동이라는 작업 흐름이 지켜지는지가 최종 기준이다.
